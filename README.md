# おうちメンテ

家庭内の家電・住宅設備・消耗品について、掃除・交換・点検の予定と実施履歴を一元管理する Next.js 製 MVP です。

## 開発

```bash
pnpm install --frozen-lockfile
pnpm dev
```

品質チェックは次のコマンドで実行できます。

```bash
pnpm lint
pnpm typecheck
pnpm test
pnpm build
```

Node.js 24 と `package.json` の `packageManager` に指定した pnpm を使います。
GitHub Actions の `Regression checks` は main 向けPR、mainへのpush、手動実行で上記4項目を検証します。
PGliteのメモリ内DBと合成ユーザーでテストするため、Supabaseの接続情報やGitHub Secretsは不要です。
CIはmigrationの本番適用・デプロイを行いません。

## 構成

- `app/`: App Router のエントリ、メタデータ、PWA マニフェスト、グローバルスタイル
- `components/`: 画面、ナビゲーション、フォーム、操作ロジック
- `lib/types.ts`: Supabase のテーブルへ移行しやすいドメイン型
- `lib/catalog.ts`: 追加・変更可能な製品カテゴリーマスター
- `lib/seed.ts`: 一般的な目安として表示するデモデータ
- `lib/date.ts`: 周期計算と日付表示

未ログイン時のデータはブラウザーの `localStorage` に保存されます。`AppData` は `homes`、`products`、`tasks`、`history` に分離してあり、後から各操作を Supabase Repository に置き換えられる構造です。
設定からデモデータを消して自分の製品を登録できます。登録画面のカテゴリ別候補は任意選択の一般的な目安です。Supabase接続時のアカウント保存と、確認済みカタログによる品番検索の基盤を実装しています。Web Pushの送信基盤を実装していますが、実環境への接続と端末への配信検証は未了です。全メーカーのWeb自動調査は未実装です。

## 情報源について

デモのお手入れ周期は実在製品のメーカー推奨値ではなく、すべて「一般的な目安」「デモデータ」として表示します。メーカー公式、取扱説明書、公的情報、一般的な目安、ユーザー設定を区別する型を用意しています。

## クラウド保存（既存共有先へ設定済み・本人操作は未検証）

保存先は既存共有Supabase `hphifiqyypwyxkzfanod`。過去の承認に基づく5件のmigrationとVercelの公開接続設定、Auth戻り先設定は適用済みです。接続先は変更しません。mainの公開版は追加機能を含まず、開発ブランチの公開はPreviewのみです。現在の適用・検証状況は `DEVELOPMENT-STATUS.md` の新しい記録を参照してください。

環境変数が未設定、または未ログインの場合は端末保存を利用します。公開クライアントはpublishable keyのみを使い、service_role/secret keyを公開しません。端末記録はログインしても削除されず、クラウド記録とは自動で合体しません。設定で移行元の住まい・件数を確認して追加できます。同じ内容の再送は重複しません。変更後の再移行は別記録として追加されます。クラウドへのJSON全体復元は提供していません。

所有者・参加家族の住まいをRLSで制限します。製品と項目の追加、完了履歴と次回更新はトランザクションで処理し、同日の完了は重複しません。保存結果が不明の場合は成功を表示せず再読み込みを案内します。本人のログイン後の保存・再ログイン・別端末の画面検証は未完了です。実DBでの権限検証とブラウザの本人操作は区別します。

Supabase標準メールは組織メンバー宛に制限され、一般利用者や家族の登録には独自SMTPの準備が必要です。メール確認を無効化して回避しません。共有Authの設定変更は他アプリにも影響するため、送信元・事業者・費用の確定後に承認を得て設定します。登録・再設定メールの実送受信は未検証です。

### 費用と移行の方針（2026-10-05）

1台・1ブラウザなら端末保存と定期バックアップで使えます。機種変更・家族共有・端末故障に備える場合はクラウドが役立ちます。既存共有先を利用し、新規プロジェクトや有料契約は作成していません。現在の契約・使用量による追加料金は未確定です。

公式料金はFreeが月額0米ドル（DB500MB、1週間非稼働で停止、自動バックアップなし）、Proが月額25米ドルから、追加プロジェクトは月額10米ドルからです。既存共有先なら新規プロジェクトの費用を避けられますが、容量・通信量は他アプリと共有します。独自SMTP事業者の料金は別途確認が必要です。料金出典: https://supabase.com/pricing 、メール制約: https://supabase.com/docs/guides/auth/auth-smtp 。契約・課金・SMTP・接続先変更は未実施です。

移行前に設定の「バックアップを保存」でJSONを保管し、本人が登録・メール確認・ログイン後、「移行する記録を確認」で住まいと件数を確認して「クラウドに追加」を選びます。クラウド側で登録製品・履歴・次回予定を確認し、再ログイン後と別端末でも確認します。移行元の端末記録とバックアップを残してください。同期はリアルタイムではなく、別端末では再読み込みが必要です。

## 品番検索の基盤

`lib/product-lookup.ts` は、正規化した品番を完全一致で検索する確認済み公式情報カタログです。確認済みの周期を持つ品番は **SHARP KI-RX75・KI-RX100、加湿器HV-T55・HV-T75・HV-R55・HV-R75、Panasonic洗濯機NA-LX129CL・NA-LX129CR**。ほかのSHARP空気清浄機は公式一覧、Panasonic空気清浄機は公式サポートページの品番を照合し、説明書を読む前は周期を提案しません。公式情報・確認日・根拠ページ・使用条件を表示し、ユーザーが確認して項目を選びます。月単位の目安を日数で予定計算する場合、その換算を明示します。該当なしは手入力へ案内します。類似型番やAI推測を公式情報に昇格させません。全メーカー・全カテゴリには対応していません。

## 検証

`pnpm test` で日本時間の日付境界、品番の完全一致、根拠保持に加え、PGlite/Postgresで実際のスキーマを適用してRLS、別アカウントからのアクセス拒否、匿名アクセス拒否、トランザクションのロールバック、重複完了を確認します。これはローカルSQL検証であり、接続先SupabaseのAuth/メール/Data APIや実際の複数端末は別途検証が必要です。

## 追加機能（開発ブランチ）

製品名・メーカー・品番・購入日・設置日・メモの編集と、製品の個別削除に対応します。お手入れ項目は名称・種類・周期・次回予定日・情報源を編集できます。削除は関連履歴も削除するため確認を表示します。周期変更時の次回日は明示的に設定します。

設定画面からJSONバックアップを保存できます。端末保存モードでは形式と関連付けを検査した後、件数を確認して復元できます。復元は既存端末記録の置き換えです。クラウドへの全体復元は未対応です。端末記録の追加移行は実装済みで、本人の画面操作は未検証です。

パスワードを忘れた場合は設定から再設定メールを要求し、`/reset-password` で新しいパスワードを設定します。Supabase AuthのRedirect URLsに本番の `/reset-password` を登録してください。実メールでの検証はクラウド接続後に行います。

## オフラインとホーム画面

192/512px PNGアイコンとmanifestを提供します。設定画面からホーム画面への追加方法を確認できます。サービスワーカーはproductionのみ登録され、オンラインで取得したアプリ画面と静的ファイルを保存します。初回はオンラインが必要です。端末保存モードではオフラインでも完了記録・再読み込みを利用できます。クラウドのAuth・APIレスポンス・家族データ、クエリ付きURL、パスワード再設定画面は保存しません。クラウドへのオフライン書き込み・同期は提供しません。更新画面の保存は必要な静的ファイルの取得完了後に行います。

## 端末記録の移行とリマインダー

クラウドにログイン後、設定でこの端末の保存済み記録を確認して追加できます。端末記録は削除しません。移行は製品・項目・履歴を1トランザクションで追加し、同じ入力の再送は重複しません。入力を変更して再移行する場合は別の記録として追加されます。`atomic_import` migrationの適用が必要です。

カレンダー出力はICS形式で、次回予定日午前9時（日本時間）から設定した日数ごとに繰り返し、前日午前9時の通知を指定します。取り込み先のカレンダーが通知を有効にしている必要があります。アプリの完了・削除・周期変更とは自動同期しません。Web Pushの実環境設定は以下を参照してください。

## 公式説明書の自動抽出

SHARP・Panasonic空気清浄機のメーカー公式PDFに対応します。Panasonicは完全一致のサポートページから、その品番の主説明書リンクを見つけて入力欄へ反映します。SHARP KI-RX75・KI-RX100は確認済みPDF URLを自動入力します。他のSHARP品番は、公式ダウンロード導線の利用条件を確認してPDF URLを入力します。両メーカーとも利用者がメーカーの利用条件を確認して同意したことを確認するまで読み取りを開始しません。利用条件への同意操作をアプリがメーカーサイトで代行することはありません。

表紙の品番を照合し、対象部品と明記された周期が同じ行にある場合だけ候補を抽出します。SHARPでは本体・後ろパネル、センサー部、加湿フィルター・トレー、Panasonicでは本体・フロントパネル、プレフィルター、タンク、トレー、イオン除菌ユニットなどの明確な見出しを対象にします。条件付きの周期、別行・別列、矛盾する周期は採用せず、AIで補完しません。月は30日、週は7日へ換算した予定であることを表示します。読み取れない項目は手入力してください。候補の根拠ページと作業条件を確認して登録します。PDF全文の再公開は行いません。

## お手入れのWeb Push

`push_reminders` migrationを保存先に適用し、Vercel Productionのサーバー側だけに `SUPABASE_SERVICE_ROLE_KEY`、`VAPID_PUBLIC_KEY`、`VAPID_PRIVATE_KEY`、`VAPID_SUBJECT`（管理者のmailto連絡先またはHTTPS URL）、`CRON_SECRET` を設定します。鍵はweb-pushの公式 `generateVAPIDKeys()` で一度生成し、秘密鍵をGitやNEXT_PUBLIC環境変数に含めません。鍵の生成・実設定は未実施です。

`vercel.json` は毎日00:00 UTC（日本時間09:00）のCronを設定します。Previewでは定期送信されません。環境設定がない場合、設定画面は「送信準備中」と表示し、送信APIは未認証401/未設定503を返します。CronのBearer秘密鍵を検証し、ブラウザは本人の購読だけ読み書きできます（最大10端末）。一時的な送信占有と送信日の記録により、通常の同日再実行と並行実行を防ぎます。送信直後の障害などで再配信される可能性は残り、通知tagで同日の通知をまとめます。失敗した送信を成功として扱わず、404/410の購読は削除します。失敗503・時間超過503は運用ログで確認し、再実行が必要です。

ホーム画面アプリを含むWeb Push対応ブラウザで、本人が「この端末で通知を受け取る」を選び許可します。期限切れと当日の項目を所有住まい・参加共有住まいから集計し、通知には件数のみ表示します。ログアウト後も配信されるため、停止は同じアカウントで設定画面から行います。このアプリのクラウド記録削除は本人の購読も削除します。実機の許可・配信・停止と、Cronの実環境実行は未検証です。

端末保存は同じ記録を複数タブで同時編集すると古い内容で上書きされる可能性があります。単一タブで利用してください。この競合の完全な解消は未了です。空文字・破損JSON・不正型の保存値は上書きせず、保存を停止します。

加湿器4機種は公式共通説明書の表紙で対象品番を確認し、14〜16ページの周期を登録しています。洗濯機2機種は公式共通説明書の印刷46〜47ページ（PDF24ページ）から週1回の槽乾燥と月1回程度・サイン表示時の予防を提案します。乾燥のたび等の使用条件を毎日に置き換えません。加湿器・洗濯機は確認済みカタログからの提案に対応し、任意PDFの自動読取は引き続き空気清浄機のみ対応です。
