# 写真・保証書の正式保存サービス

`/api/product-attachments` は正式接続用に準備した経路です。現在は無効です。`OUCHI_ATTACHMENTS_ENABLED` は設定していません。本番・Previewへ設定を追加したり、共有DBへ変更を適用したりする作業は、この変更に含みません。

## 無料と有料

新規保存は、Authで検証したセッションと現在の登録世代に対する、署名検証済み台帳の有料利用権が必要です。SandboxとProductionを混在させません。写真の実サイズ・形式・ハッシュ、住まいへのアクセス権、予約容量、書込み試行をサーバーで確認します。通信失敗時に別IDを発行して再送したり、不確かな予約を消したりしません。

保存済みファイルの取得・書き出しは契約終了後も利用できる設計です。有料利用権の照会を行いません。現在のセッション・登録世代・住まいへのアクセス権は必要で、ファイルの取得後にも再確認します。退会や家族共有から外れた場合は取得できません。

開発経路と正式経路は同じ取得処理を使います。正式経路の利用には、検証済み台帳、HTTPSのSupabase接続、独立した明示的な有効化が必要です。これらの設定値だけではApple購入や公開準備が完了したことにはなりません。

## 有効化前の残作業

- iPhoneの製品・設定画面と正式通信処理への接続は準備済みです。Info.plistの `OUCHI_ATTACHMENTS_ENABLED` はfalseです。開発環境だけ明示的にローカル接続できます。公開ビルドはローカル接続指定を無視し、HTTPSの正式経路へ固定されます。実サービスで画面からの一連の動作を検証する。購入前に容量・保存条件を表示する。
- Webの製品画面に保存済みファイルの一覧・取得を接続しました。`NEXT_PUBLIC_OUCHI_ATTACHMENTS_ENABLED` は未設定で、画面は非表示です。端末保存のデモデータでは表示せず、クラウドアカウント・住まい・製品に固定して表示します。アカウント切替で通信と表示を破棄し、一覧/取得の後にも登録世代を照合します。新規保存と応答喪失後の同じIDでの再確認を画面へ接続しました。削除画面は未接続です。隔離した仮サービスの検証を、実サービスの完成として扱いません。
- Webの確認待ちファイルをIndexedDBへ保持する部品を準備しました。アップロード画面・通信へ接続しました。アカウント/登録世代に固定し、同時操作でも既存IDを上書きせず、端末側のコミット確認後にのみ送信用の記録を返します。受領した同じIDだけを完了として消去します。元のファイル名・パスワード・トークンは保存しません。IndexedDB自体の暗号化を保証するものではありません。このアプリの明示的なログアウト前にアカウント全世代の確認待ち本文を消去し、その後の保存をブロックします。消去のコミット失敗はログアウト成功として表示しません。新規ログイン/登録の成功後に端末保存を明示的に再開します。認証期限切れ・他端末からのログアウト・完全退会完了時の自動消去は未接続です。
- 正式なPOST/DELETEは `X-Ouchi-App-Epoch` に非ゼロUUIDがなければDB接続前に拒否します。認証後、現在のSQL登録世代と照合し、不一致の場合は予約・Storage・削除処理を行いません。iPhoneの保存/削除は直前のbindingで確認した世代を送信し、正式クライアントは世代がない要求を送信しません。既存の隔離開発テストのみヘッダーなしの互換処理を残します。これを本人確認や購入権利として扱わず、Auth・現在のセッション・登録世代・住まいへのアクセス・購入権利はサーバー側で別途確認します。Webの送信画面も確認した世代を固定し、送信前と成功応答後にサーバーへ照合します。
- Webの保存/削除クライアントも、確認した登録世代・同じファイル本文・同じID・明示的な確認を送信する処理を準備しました。サーバーから同じIDの成功確認が返らなければ完了にしません。保存画面は、IndexedDBのコミット後に保存済み本文を読み直して送信します。再読み込み後は利用者が確認待ちファイルを確認し、同じIDで再確認します。自動送信は行いません。削除画面への接続は残っています。
- 容量案はアカウントごと100MiB・100ファイル、1ファイル5MiB。現在のコード制限であり、保存期間・退会・バックアップ消去条件と併せて正式な規約へ確定する。
- 共有DBの追加変更・非公開Storage・RLS・実Auth/Storageを隔離環境で確認する。実際のApple Sandbox購入権利で一連の動作を検証する。
- 新規保存、取消、応答喪失からの同じIDでの復旧、期限切れ後の取得、家族共有解除中の取得拒否、普通の製品/住まい削除時のファイル消去を確認する。
- 完全退会と有限な保持条件を完成させる。識別情報の最終消去が未実装の状態で販売しない。
- 本番統合・有効化について本人の承認を得る。新たな有料インフラ契約や実際の請求を行わない。

## 今回の検証範囲

合成DBで経路の無効化、設定・method・曖昧なquery拒否、Production台帳で無料ユーザーの新規保存拒否、期限切れ後の取得、取得中の共有解除を検証します。実Auth/Storage・Apple購入・正式画面は、このテストでは証明しません。

iPhoneの実URLSessionを仮HTTPサーバーへ接続し、ファイル本文・ID・形式を保った保存/取得/削除、応答ヘッダーとストリームの上限、転送拒否、キャンセル済み処理を確認します。仮サーバーは合成の応答を返し、本物のDB、Apple署名済み購入、正式画面からの保存成功を証明するものではありません。テスト環境で虚偽のContent-Lengthを返した最初の試験は、サイズ拒否ではなくHTTP不正応答となりました。宣言と実際の長さが一致した大きい応答へ修正し、境界拒否を確認しました。

Webの確認待ち保存は合成ドライバーの5件の検証に加え、一時プロファイルの実Chromium IndexedDBでコミット、ブラウザ終了/再起動、再読み込み、別タブからの参照、同時保存の競合、登録世代分離、同じIDの完了処理、元ファイル名の除外を確認しました。API要求は0件です。実サービスの保存成功や完全退会の消去は証明しません。テストはローカルにあるPlaywrightとブラウザを明示的に指定し、ブラウザをダウンロードしません。

Webの実React画面・実ブラウザIndexedDB・fetchを、一時的な仮Nextサービスへ接続して確認しました。保存後の応答を失う503、ページ再読み込み、利用者による同じIDでの再確認、仮オブジェクトが1つだけであること、同じIDの確認待ち消去、一覧・ダウンロード、アカウント切替時の表示消去を確認しました。390px幅の表示も確認しました。仮セッションと仮Storageだけを使い、本人アカウント・実Apple購入・実Auth/Storageは使っていません。明示的なログアウト時のIndexedDB消去は接続しました。

明示的なログアウトの端末消去は同じIndexedDBの書込みトランザクションでアカウントの許可世代を更新し、全登録世代の本文を消去します。消去前に許可を取得してハッシュ計算中だった別タブの保存は、古い許可世代で書き戻せません。消去後の新規保存も、ログインによる再開まで拒否します。仮アカウントの実ログアウトボタンと、別タブでハッシュ計算を止めた実IndexedDBの競合を検証しました。他端末からの失効や別タブの古い認証が新ログインと重なる動作、完全退会の端末消去をこの検証で完了としません。端末消去はクラウド保存の取消や削除を意味せず、曖昧なクラウド書込みの清掃は別途サーバーで完了させる必要があります。
