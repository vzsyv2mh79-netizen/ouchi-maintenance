# Prepared formal maintenance report

`GET /api/maintenance-report` is disabled unless `OUCHI_REPORTS_ENABLED=true`, billing configuration is a verified ledger with HTTPS Supabase URL, and a publishable key is configured. Production billing configuration additionally requires the existing Apple application/verification safeguards. This change sets no flag, creates no paid infrastructure and deploys nothing.

The caller sends its bearer, one UUID homeId and the app epoch it previously confirmed in `X-Ouchi-App-Epoch`. Auth verifies the exact token before session claims are used. The service client reads the current enrollment and selected-environment server ledger; free/expired rights never construct a household client. Household loading and final home-access recheck use the caller JWT plus existing RLS, never service privileges. Auth, epoch and ledger rights are rechecked after loading. A changed binding, lost membership or expired subscription discards the report. An unavailable service is retryable, not evidence of paid access.

The response is no-store, bounded to two million UTF-8 bytes and includes environment, confirmed purchase-account token and report. The report counts registered products/tasks, current overdue/today tasks and six months of recorded completions using Japan dates. It does not infer fault or safety. Basic records/history and export remain free.

The existing development report API is unchanged. Its legacy test-grant path is not accepted by the formal endpoint. Native formal UI wiring and selected environment/epoch response validation are prepared behind a checked-in disabled flag; see ios/Docs/FormalReport.md for verification scope. Native and Web formal UI wiring are prepared behind disabled gates. Web display requires NEXT_PUBLIC_OUCHI_REPORTS_ENABLED=true and an explicit NEXT_PUBLIC_OUCHI_REPORT_ENVIRONMENT matching the configured server ledger; these are public availability configuration, never credentials or entitlement authority. No public gate is set by this change. Real selected-environment native/Web service/device verification and rendered/device verification of expiry and suspension remain required. Do not advertise a purchasable released report benefit until those connections, actual Apple entitlement tests and release verification are complete. Prepared unit tests cover disabled configuration, ambiguous requests, exact ledger scope, expiry/auth/epoch/membership changes and outages. Disposable Auth/PostgREST/ledger integration uses synthetic purchase seeds; it is not an Apple signature or production endpoint proof.

## Prepared Web connection and verification scope

Cloud settings mounts ReportControls keyed by account and selected home. loadWebReport reads current session, snapshots account/token values, checks selected-environment server ledger before and after the formal endpoint, and matches returned enrollment/home. It rejects redirects, wrong response URL, MIME/cache policy, invalid report dates/counts and declared/streamed bodies over 2 MB. The whole fetch flow has a 30-second abort deadline. Display is transient, not persisted: expiry/five-minute wall and monotonic deadlines, auth events, hidden document, pagehide and unmount invalidate it. Client availability flags do not grant access; the formal service still enforces Auth/RLS/verified ledger. Returned errors leave records and free export unchanged.

Four new unit groups cover successful three-request flow, auth/token mutation, epoch/environment/home/expiry changes, schema consistency, transport bounds and display lease deadlines. A real browser renders the actual component at 390 px and calls synthetic Next API routes; it verifies auth loss, late response refusal, home switching and foreign-home refusal. This does not verify real Auth, database, Apple entitlement or production deployment. The independently verified backend integration uses disposable Auth/PostgREST and synthetic ledger seeds; complete browser-to-real-service testing is still required. Screenshot web-report-mobile.png is a fixture screenshot, not an App Store marketing asset.

The first unit run found that a mutable session object could change captured comparison values; production now copies account/token scalar values before awaiting. Unit groups passed after repair. The first full regression run was refused by sandbox localhost restrictions, not treated as a passing test. No production configuration, billing or deletion has been activated.
