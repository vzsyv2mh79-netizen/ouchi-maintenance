# Prepared formal native notification registration

FormalNativePushAPI pins /api/native-push-registration to the production HTTPS host, blocks redirects, uses ephemeral URLSession, bounds declared/streamed replies to 4096 bytes and requests to 30 seconds, and refuses foreign response URLs, MIME/cache policies, enrollment or environment mismatches. Only explicit Debug Sandbox/Sandbox fixtures may use loopback. APNs environment is NativePushEnvironment, separate from purchase BillingEnvironment. Register/disable send the exact bearer/current X-Ouchi-App-Epoch and a body containing only the device token or registration ID; tokens are not logged or persisted by this API. A false disable acknowledgement is not a successful stop.

NativeStore exposes the prepared screen only when Info.plist OUCHI_NATIVE_PUSH_ENABLED=true and both OUCHI_APNS_ENVIRONMENT and OUCHI_NATIVE_PUSH_PURCHASE_ENVIRONMENT are explicit supported values. All defaults remain disabled/Sandbox. Registration is free: it checks verified ledger enrollment before/after, not premium membership. Account, generation, binding revision, selected home and cancellation are rechecked across every awaited operation. An exact receipt is retained only in view state; different-account/different-epoch/different-environment receipts cannot be used to disable a destination. An unknown acknowledgement is not proof that the server rolled back. Re-registering the same token in the same scope provides an idempotent confirmation; stopped destinations require a new registration. There is no automatic cleanup using a replacement user's credentials.

The screen cancels and clears its receipt on account/home binding change, background and disappearance. Inactive state alone does not cancel, because the system permission dialog can make the app inactive. Missing local receipt means unconfirmed status, never that the server destination is disabled. Stop acknowledgement is shown only after true and matching enrollment verification. Registration does not start a scheduler or send messages, and the screen says delivery is still prepared.

Verification: 31 freshly compiled synthetic smoke programs including separate distribution-APNs/Sandbox-purchase receipt tests, macOS Debug/Release NativeStore typecheck, UI parse/project/plist/privacy checks, and an isolated unsigned iOS Debug build. FormalNativePushHTTPIntegration uses real URLSession against a synthetic loopback server: twelve register/disable/invalid response cases, zero redirects/cancelled-network requests, exact headers/body, negative disable, declared/stream bounds and cancellation. It does not verify live Auth/PostgreSQL, real device permission/registration, owner data or Apple signatures; the backend disposable integration is separate evidence. NativeStore asynchronous account switching, rendered UI, real system permission dialog, device token registration and TestFlight/APNs delivery remain real-flow release checks.

Release work includes Production server device/job/dispatch wiring and scheduler, independent APNs/purchase deployment configuration, Web/native overlap policy, registration confirmation after restart and real lifecycle/account/device tests. Sale and notification feature flags remain held. No shared database migration, payment, paid infrastructure, owner deletion or actual push was performed.
