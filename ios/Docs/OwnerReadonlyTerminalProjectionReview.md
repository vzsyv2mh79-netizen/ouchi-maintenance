`createOuchiOwnerReadonlyTerminalProjection({key,scope,completionLease})` in `lib/ouchi-owner-readonly-terminal-projection.ts` returns `read(tx)`. Supply a trusted server-owned **already READ ONLY PostgreSQL transaction** with `signal` and parameterized `query`. There is no `beforeCommit`, held binding or execution lease interface. The fixed private RPC `maintenance_private.read_ouchi_owner_terminal_projection(uuid,uuid,jsonb,uuid)` is in `tests/fixtures/ouchi-owner-readonly-terminal-projection.sql`. Its caller is the existing exact `shared_retirement_backend` nonprivileged LOGIN with no role memberships; no new caller grant is included outside the disposable native fixture. A different hosted read role needs a separately reviewed ownership/ACL profile.

This is a STABLE, SELECT-only SECURITY DEFINER projection at the caller statement snapshot, with no explicit row/advisory lock, GUC mutation, `txid_current` allocation or call into the old locking terminal reader. It requires transaction_read_only=on; a read-write invocation returns no fact. The session-custody equality is inlined as reads to avoid calling the old VOLATILE helper. The canonical native completion helper must be STABLE/INVOKER. Its current approved definition/ACL remains part of deployment review.

The SQL requires true complete root status, both lease fields null, exact whole stage grammar (fifteen for the two-app scope), the exact extended family receipt bound to the immutable empty-family checkpoint/token/digest, immutable owner-zero closure with the original root lease, native mapping and completion lease, unchanged original record, full session custody, canonical native seal and unextended receipt expiry. The scoped binding must be closed and the stopped principal tombstone remain present. Auth/session and owner-family absence are snapshot conditions, not insertion barriers. Original/closure/session guards must still be enabled as specified. No naked empty array, lease clearing, missing row or plain COMPLETE flag is enough.

The server wrapper independently checks the exact original HMAC/signature/domain/scope/session/epoch/expiry arithmetic and the returned read-only snapshot metadata. It returns only `{state:'complete',notification:'unconfirmed',retention:'unconfirmed'}` or `{state:'unconfirmed'}`. The raw private original, IDs, signature and snapshot are not included in the public projection. Malformed facts or signatures throw so a transport must fail closed. Original expiry may be historical; it is not renewed fresh identity. Native receipt expiry still bounds the sealed completion read.

**This projection is not a standalone authorization or execution capability.** A separate HTTP boundary must resolve the trusted scope, authorize the finite pre-custodied hashed result credential, enforce request deadline/origin/rate controls and avoid caching/logging token material. It mints or registers no credential and cannot replace the pre-processing identity/custody/claim gate. A snapshot observation does not hold current Auth/DDL/old-JWT exclusions through a later COMMIT, deliver a notification, adopt a retention SLA or authorize repeating erasure. Current exclusion continues to use the unchanged execution/terminal binding ports.
