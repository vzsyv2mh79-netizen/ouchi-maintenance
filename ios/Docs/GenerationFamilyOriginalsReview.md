# Generation-bound family AAL2 originals and claim

2026-10-21. Disabled local empty-file family candidate. Extends verified family native preparation with immutable generation originals and an exact requested→processing claim. **No handoff, post-handoff canonical capture, file/capacity handling, paired public-intake claim integration or hosted activation.**

## Fixed server contract

`createGenerationFamilyOriginals({scope,generationID,nativeLease,homes,key,projectID,policyReader,getUser,verifyNoDispatch,clock?})` accepts a complete frozen home/successor roster, an independent copied signing key and current trusted policy/Auth providers. No supplied identity verdict or arbitrary SQL. Scope/targets/key are copied. Current no-dispatch/privileged-writer/remaining-path admission is mandatory through owning COMMIT.

- `issue(bearer,homeID,tx)` is dedicated-issuer, requested-only. It reuses the existing strict scoped bearer verifier via one fixed generation Auth RPC, adding the actual private enrolled epoch. The original strict FK/Auth/session/factor/AMR/timebox/inactivity checks are preserved; the fixed plan input now derives from the immutable generation, preimage, complete targets and native lease. No raw password/factor/session data leaves the private digest function.
- `readOriginal(homeID,actor,tx)` is a hook-free current snapshot, not mutation authority. It binds the full configured scope/targets/lease, phase (requested or early processing), policy and no-dispatch before/after, pins actual PID/XID, verifies private current Auth/epoch and independently checks the exact HMAC. Caller owns transaction rollback on exceptions. It is not a READ ONLY HTTP/result capability reader: private RPCs lock Auth/root/native rows.
- `requested(scope,tx)` requires every home owner's original and every selected successor's original, returning only an opaque object owned by that factory and exact transaction. No raw original DTO goes to the root claim gate.
- `adopted(scope,EXACT opaque,EXACT tx)` rereads all original fingerprints after the formal requested→processing transition with the same actual PID/XID and planned root lease. The root's claim-ready callback must register this hook before final checks begin. It is hook-free so it may run inside the owning final check.
- `verifyProcessingOriginal(scope,tx)` independently verifies the complete original set in the exact **early processing / empty receipts / pre-handoff** frame. It is not a general post-handoff/worker/post-Auth reader. All these current readers may fail closed or throw transaction errors; never ignore a failed callback and commit a mutation.

The new private payload has exactly twelve canonical fields: domain, requestID, generationID, homeID, userID, epochID, sessionID, aal, authenticatedAt, authStateDigest, proofDomain and expiresAt. Its separate signature domain is `OuchiMaintenance/family-generation-original/v1`. The Auth digest remains the strict scoped-auth proof domain but includes the generation-derived immutable plan/preimage and native lease. Old legacy originals cannot be relabeled. Payload/signature/policy settings are stored in an immutable generation/home/actor record without an Auth FK. No bearer or signing key is persisted.

Expiry stays tied to the actual verified original TOTP authentication time (the existing 600000ms freshness contract), not a new clock-based authentication or renewal. Replay preserves exact payload/signature/expiry. Cancellation and same-home reapplication preserve old originals; new generation signatures differ and require fresh issuance under the new exact frame. Reusing the same still-fresh TOTP session does **not** extend its expiry. This freshness rule is not a retained-data TTL or approved operational retention policy.

## SQL and final COMMIT

Generation/native preparation, exact original scope, complete roster, stopped fence, disabled enrollment, empty personal/household-file/review scope and native captured=false must remain unchanged. Root is requested with null lease fields, or early processing with the exact live planned lease and empty receipts. Missing/null processing expiry refuses explicitly. Auth parent/factor/session/AMR rows and root/native/home rows are locked under the established root-first and sorted-participant order.

Private issuance accepts only the dedicated issuer and requested phase, exact payload keys/types, actual epoch/digest/time and immutable equality on replay. Runtime coordinator cannot write table rows or call the issuer RPC. Private current readers recheck the original session, current policy settings and actual epoch; JavaScript separately verifies HMAC.

The old native/reservation deferred checker receives an exact processing branch requiring the complete still-current issuer original set; its prior branches remain verbatim. A separate ALWAYS deferred trigger fires on the root's requested→processing UPDATE and checks the original set at actual COMMIT, including raw-transition attempts. This SQL check complements the server HMAC/current-policy/coverage adoption hook; it does not turn a client JSON flag into authority. The existing global processing/COMPLETE guard is not replaced. No legacy plan PK, original row, canonical capture/eraser, session manifest or result expiry is changed.

## Evidence and limits

Actual PostgreSQL17.6/GoTrue2.197: one owner, two distinct successors and two homes, all with real password/TOTP sessions and enrolled epochs. Owner-only, one-home-only or missing-successor sets cannot claim. Raw requested→processing without originals and with null lease expiry fail at COMMIT. Exact immutable originals replay without renewal; cancel/reapply retains all four older originals and requires all four new ones. Wrong signing key/full scope, AAL1 and cross-transaction opaque proofs refuse. Actual journal claim/adopted/final deferred COMMIT succeeds; late policy loss rolls the root transition back. Fresh early-processing original check succeeds; processing issuance refuses. Immutable/raw table access guards hold. Ownership/products remain unchanged; native canonical captured=false.

The root in this test is the captured shared journal fixture, with exact local RLS policy. It is **not** independent proof of the current public requested_at intake, both-app claim registry, result-credential/outbox lifecycle or real production completion guards. Sibling paired cancellation success is separate evidence, not adopted here as claim proof.

This is NOT a reviewed hosted least-privilege owner/ACL profile. Full writer/DDL/Storage admission, operator recovery, personal original/session/preimage retention/access policy, migration and activation remain separately unapproved.
