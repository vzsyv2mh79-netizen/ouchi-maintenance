# Prepared formal native reminder transport

FormalReminderSettingsAPI is separate from the existing development ReminderSettingsAPI. A caller supplies the selected BillingEnvironment and a nonzero enrollment UUID for each load/save. Requests use GET/PUT /api/reminder-settings, a bounded bearer and X-Ouchi-App-Epoch. Release pins the HTTPS application origin; Production ignores loopback options even in Debug. Default URLSession refuses redirects and bounds declared/streamed response bytes to 4096.

The response must match exact URL, MIME type, no-store, selected environment and enrollment. It requires explicit saved:null for revision zero, coherent saved/effective settings and an exact revision/value save acknowledgement. Free/expired rights retain preferences but use the free schedule. A failed acknowledgement is not proof a save rolled back: callers must reload or retry the same revision/value. The transport itself does not cache entitlement, schedule a notification, enable sales or expose any screen.
