# Free notification channels — prepared, disabled

The Settings link requires OUCHI_NOTIFICATION_CHANNELS_ENABLED=true and an explicit OUCHI_NOTIFICATION_CHANNEL_ENVIRONMENT (Sandbox/Production) in app Info. No flag is added or provisioned. FormalNotificationChannelAPI pins HTTPS and the fixed channel path; debug loopback is limited to Sandbox. It bounds streaming and declared lengths, refuses redirects/foreign URL/MIME/cache, requires exact receipt keys, account enrollment/environment, safe revision and acknowledgement of the requested channel. Channel selection is free and does not inspect premium validity to authorize a write.

NativeStore reads verified enrollment before/after API access and checks account/session token, generation, home, and account binding. A returned selection is transient with both wall and ContinuousClock five-minute validity. Save requires a fresh prior receipt; an unconfirmed acknowledgement never creates a selection and requires reread. The Form disables saves without a current selection, and native-only saves without confirmed registration. Binding changes, background and disappearance cancel operations, discard choices and clear local status messages. The registration prerequisite is not proof of actual APNs delivery.

An explicit confirmed button stops only this account's pending app-owned local requests on this installation. LocalReminders increments its generation to interrupt concurrent scheduling, checks current binding/cancellation before and after pending lookup, removes exact scoped requests, re-reads pending IDs and clears the matching preference only when absence is confirmed. It refuses ambiguous legacy requests. Delivered requests and foreign-account/unrelated requests are preserved; a failed confirmation does not claim opt-out. This stop does not enable remote delivery, and the UI warns it may leave the device without notifications while remote delivery is held. It is never invoked implicitly by registration or channel save. Other offline installations cannot be recalled; production activation must require each installation's opt-out/setup and real account-switch/restart evidence.

Validation uses compiled synthetic API transports for free channel receipt/read/write, exact revision/value, scope, invalid keys/types, bounds/cache/MIME, foreign URL, rejected responses and cancellation. Injected local backend tests cover pending-only stop, failed removal, binding change, exact-account preservation and idempotence. A sanitized unsigned iOS Simulator SDK build compiles the actual Form. These do not prove live Auth/device permissions, OS cancellation, real URLSession transport, APNs or Apple purchase behavior. Server disposable Auth/PostgreSQL/API proof is separately documented in docs/REMINDER-RELEASE-GATE.md. Shared migration, signing, real-device and release tests remain held.
