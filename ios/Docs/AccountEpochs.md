# アプリ単位の再登録・購入世代の隔離（ローカル試作）

account-epochs-prototype.sqlは本番マイグレーションではありません。共有Authを残したまま、おうちメンテの登録世代をランダムUUIDで区別します。明示的な再登録は新しい本人確認済みセッションにだけ結び付け、古いセッションと購入世代は新しい登録に使用できません。古い削除要求が遅れて到着しても、新しい世代を無効にしません。

PGliteの独立DBで、ブラウザー権限による登録拒否、旧セッション拒否、旧購入世代拒否、他ユーザーの維持、再登録失敗時のロールバックを確認しました。共有Authのユーザーは削除しません。

未完了: 実Authのsession_id検証と最近の再認証、登録API、Web/nativeのセッション継続、RLSと全RPC、購入APIとApple通知への世代接続、旧ファイルと個人情報の削除、マーカーと取引情報の正当な保持期間、競合実行試験。セッションUUIDはクライアント入力を信頼しません。閉鎖後のログイン・トークン更新で自動再登録しません。

Appleのアカウント削除要件を満たしたとは扱いません。既存account_access試作とも未接続で、本番に適用・有効化しません。本人や家族のデータをテストに使いません。

統合試験account-epoch-rls.test.mjsは既存の住まい・共有・通知・復元マイグレーションとアクセス制限試作を独立DBで読み込み、登録世代と合成JWTのsession_idをRLSに接続します。削除後に新しいセッションで再登録しても、古い・別ユーザー・欠落・不正なセッションによるSELECT、load、create、UPDATEは拒否され、新しい記録は旧セッションから見えません。他ユーザーは利用を継続できます。実AuthによるJWT署名検証や本番セッション移行を確認した試験ではありません。

close_app_identityは世代確認・停止・住まい等の既存クリーンアップを、reenroll_app_identityは新世代のセッション登録・アクセス再開を単一取引で実行するテスト専用関数です。途中に例外を発生させ、削除と再登録のどちらも関連変更をロールバックすることをDBで検証します。実際の個人情報削除対象・保存領域・サーバーAPI・本番移行は未完了です。

ローカル専用清掃APIはgetUserで当該Bearerを確認した後、トップレベルsub/session_id/expを検査します。user_metadataのセッション情報は使用しません。抽出関数自体は署名検証器ではなく、必ず認証サーバーの確認後だけ呼びます。service専用close_maintenance_app_identityはそのセッションと現在の登録世代をDBで照合してから清掃します。旧セッションやブラウザー権限の呼び出しを拒否します。実Authでの統合確認、保持データの完全削除、MFAと本番適用は引き続き未完了です。
