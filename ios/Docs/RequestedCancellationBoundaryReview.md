# Unprepared requested-root cancellation guard — local candidate

2026-10-21. This is deliberately a boundary guard, **not the final prepared-request cancellation solution**. No native request or household fence is deleted/reopened, no original/manifest is erased, no token is minted, no retention period or production setting is adopted.

`createOuchiRequestedCancellation({verifyCoverage,signal})` in `lib/ouchi-requested-cancellation.mjs` returns `cancelRequested(scope,tx)` and `verifyCancelled(scope,tx)` for the root journal's same-transaction after-cancel hook. `verifyCoverage` must independently cover current dispatch/unknown outcomes/all writers and the exact affected apps through COMMIT; it has no default. The SQL guard is `maintenance_private.ouchi_requested_cancellation_state(uuid,jsonb)` in `tests/fixtures/ouchi-requested-cancellation-state.sql`. The exact restricted caller is `shared_retirement_backend`; the SQL-owner/effective grant profile is not approved for hosting. No caller grant is included outside the disposable native fixture.

The root must already be cancelled on the same physical transaction, have exact frozen scope, empty receipts and both lease fields null. The actor must still have real Auth, an enabled current Ouchi epoch/access and a live bound session. The guard holds the existing principal advisory key and Auth KEY SHARE parent. It refuses every actual native request for this epoch (including pending), active requests on the actor, stop binding/stopped fence, family plans/holds/worker capabilities, original/consent, native/family inventory/custody/cleanup/release/terminal records or deletion/receipt/review/result artifacts. Missing known tables refuse; unknown new writers/storage remain the outer coverage gate, never a prefix exclusion. The methods do not mutate app data or assert restoration.

The wrapper checks physical PID/XID and current SQL facts before/after independent coverage. If the root transport has beforeCommit, a refusal poisons its owning COMMIT and a final verifier repeats the facts. A raw pinned root transaction is supported for the existing coordinator, which must throw/ROLLBACK on every false/error and own final current coverage. A successful old pristine cancellation never edits a newly requested root. If a new actual native request has appeared, old verification refuses rather than reopening anything.

## Existing intake mismatch requiring the next protocol

The current owner-only issuer requires native state running with inventory captured, disabled account_access/app_epochs and processing household stop/fence even while the shared root remains requested. See the fixed owner-only frame and native test setup. Those rows have **no pre-prepare restoration image**. A root requested flag alone therefore cannot justify reopening them. Current native request states have no cancelled value; the request row also has a unique(user,epoch) constraint and request RPC reuse. Deleting/rewriting such requests, inventing enabled flags, adding a cancelled enum without auditing claim/progress/open-account predicates, or retrofitting a guessed snapshot would be unsafe. This guard refuses them.

The next candidate must save minimal, exact original state and the legitimate prepared footprint before any new preparation, on the same root/native/epoch and actual transaction. It must independently fence writers, preserve originals and family assets, reject processing/handoff/copy/erase/logout/foreign-generation or unknown drift, and restore only provably reversible effects. Legacy prepared rows without provenance must remain refused. This file does not claim that protocol is implemented.

## Actual local evidence

PostgreSQL17.6/GoTrue2.197 native test: a fresh real Auth actor with explicit fixture enrollment, retained home/product and no native preparation can cancel the root through the actual journal callback. Actual pending/running native requests, a stopped fence, missing known schema and late coverage loss refuse and leave root/app state unchanged. Late refusal rolls root cancellation back. Repeated journal cancellation does not release again; new root reservation stays unchanged, and a new pending native request refuses reversal. All homes/products, the previously issued real owner originals/session manifests and real Auth remain unchanged. Actual canonical review table definitions are loaded where needed; no stand-in cancellation storage table supplies app success.

The coordinator's Kakei generation/public-request/result-token/outbox composition is not executed by this Ouchi local test. Enrollment/coverage are explicit fixtures, not hosted all-writer/dispatch approval. Local unit tests cover required coverage/deadline, false/poisoned final checks, scope/PID/XID drift and raw root transport. Existing prepared-owner cancellation remains blocked as above. This candidate changes no existing execution reader or canonical prepare/cancel function.
