# Unused generation file preparation cancellation — local review candidate

This extends `689754f` COPY PREPARATION only. It cancels ALL per-file bindings of
one planned generation only when EVERY copy is genuinely NEVER ISSUED. It does
not make a photo-bearing canonical native generation, activate retained custody,
delete any physical object or source metadata, release capacity, erase Auth,
complete account deletion, or release a handed-off family's ordinary writes.
All changes are prepared fixture/server source, not a hosted migration/adoption.

## Exact eligibility and current inspection

`createGenerationFileCancellation` requires a mandatory independent SERVER
`verifyCancellationAdmission(scope,tx,signal,phase)` and bounded private Storage
read/inspect ports. `preparing` verifies current cancellation ownership and target
namespace writer custody; `committing` verifies the final intended cancelled
root and all independent app/contact/key cleanup. This authorization is separate
from a withdrawn copy/retention approval: safe unused reversal never renews it.
There is no client flag or default policy/retention TTL.

The exact safe `shared_retirement_backend` LOGIN, no inherited role membership,
whole scope, planned generation/native lease, requested root/empty receipts/no
lease, active app epoch/access and absence of native retirement are required.
Root-first row locks, stable participant advisory locks and selected file/intent/
destination row locks span the owning transaction. Every selected intent must be
reserved, unstamped as copied and have ZERO writer rows. Even `not_dispatched`
history is conservatively refused by this first version. Issued, acknowledged,
legacy-unknown or verified copies refuse the WHOLE cancellation; none are timed
out into permission to cancel.

Source and staged destination UUID/path/home-incarnation/product/hash/size/MIME,
original review/decision/operator binding, quiet source writes and held exact
capacity must still match. Known incoming FKs are allowlisted by exact schema,
table, column and parent key/shape and must be empty (except the selected own
intent). That includes `household_removal_capacity_moves`, which must NOT be
ignored or erased. Unknown child storage refuses even when empty. Existing
removal receipts/origins/retirement queues, existing destination objects or
retired/reused IDs refuse.

Before SQL undo AND immediately before COMMIT the server freshly downloads and
measures every original source and requires genuine typed Storage `NoSuchKey`
for each destination. SQL also checks Storage object metadata absence. A timeout,
503, generic false, wrong bytes, wrong MIME, a destination appearing late, or a
physical PID/XID change is never absence. No unverified cache is used. Namespace
writer coverage and controller authorization still require independent operating
approval; the test provider/gateway do not establish that deployment coverage.

## Atomic root composition and retained audit

Call `port.prepare(scope,tx)` BEFORE the existing `journal.cancel(scope)` work on
the SAME checked dedicated root transaction. The journal must update only the
root status from requested to cancelled in this transaction, followed by the
existing independent all-app/key/contact hooks. The registered final check runs
after those hooks. An app-only undo, a missing root cancellation or any last
refusal rolls the entire SQL change back. No Storage side effect needs rollback:
this cancellation adapter has no POST, upload, remove or cleanup method.

Immutable cancellation provenance archives exact before-images, measured
observations, original binding/header and actual producer PID/XID. Only exact
selected never-issued intents and staged-destination metadata are removed.
Sources, members, owners, products, maintenance records, enrollment/Auth and
other families' files stay unchanged. Both unused destination IDs are permanently
retired BEFORE metadata removal. Existing capacity claims remain byte-for-byte
held; no capacity or provider-wide physical GC/billing settlement is inferred.

The previous binding→intent FK belongs to this new preparatory sidecar, not to
Auth or a legacy plan. In this review fixture ONLY that exact deferred FK is
replaced by an exact cancelled-history exception, ALWAYS producing-COMMIT checks
and exact-context DELETE guards. Immutable binding/header originals remain; a
non-cancelled binding cannot silently lose its intent. The two prior file guards
keep their exact hashed original bodies as fallback. No old plan PK, canonical
capture, copy nonce/ACK body or existing original/expiry guard is weakened.

`readCancelled` is scoped private historical fact, not current cancellation or
erasure capability. A lost real COMMIT acknowledgement recovers that immutable
receipt without another Storage request or metadata undo. Same-source/new-root
reapplication obtains new intent/destination/generation bindings; the old receipt
cannot reopen it or bypass the new pending-copy source guard. Existing content
review history stays scoped and preserved; the root still owes new generation
consents/key/contact/intake authorization independently.

## Evidence and limits

The explicit `OUCHI_FILE_CANCELLATION_TEST=true` native profile ADDS these probes
to the full prior copy tests; it skips no old copy case or safety check. It uses
full pinned135 canonical schema, PG17.6, the pinned official Storage API with
filesystem/PG metadata and actual normal journal cancellation. App/Auth identities
and the cancellation/coverage provider are SYNTHETIC; this is not real paired
public intake/Auth ownership or an iPhone confirmation.

The added native cases cover two-file unused undo, copy approval withdrawal with
separate cancellation authorization, rootless partial commit refusal, unknown
empty FK/known nonempty capacity-move refusal, HTTP failures, final contact and
late authorization rollback, late real destination appearance/whole SQL rollback,
lost root COMMIT reply, permanent ID reuse refusal, source/new-root reapplication,
old-history/new-pending isolation, and mixed dispatched/verified/existing-target
whole-root refusal. Original bytes, family/app/Auth metadata, immutable header/
bindings and held capacity are checked. Receipt readback does not repeat I/O.

Still unconnected: real paired public cancellation/contact/key and current Auth
admission; provider reconciliation or cancellation of any issued/closed writer;
full file inventory and BOTH actors' inventory originals; staged household
activation and scoped physical source erasure/finalization/lost DELETE handling;
actual file-capable canonical generation; paired file stages/global erasure/
Auth-after/COMPLETE/family-write release; hosted roles/all writers/retention
adoption. The root's separate paired3stage and expiry proofs are external evidence,
not a proof of these photo routes. No production, real user deletion or charge.
