# Owner-only terminal transition — local review candidate

2026-10-21. Undeployed, no shipping route, Auth removal, billing, migration, role provisioning or live permission change. This is a separate owner-zero capability; the processing readers and the family-hold release retain their existing requirements.

`lib/ouchi-owner-terminal-consent.ts` supplies `createOuchiOwnerTerminalConsent`, `createOuchiOwnerTerminalClosure` and `createOuchiOwnerTerminalResultReader`. The review SQL is `tests/fixtures/ouchi-owner-terminal-consent.sql`. Read/closure factories use the same options as the owner post-Auth reader, but their mandatory Auth fence must come from **`held.bindTerminal`** plus independent remaining Auth/DDL/all-app coverage, never a reused processing binding or a client flag. The result reader additionally requires a trusted `authorizeResult` callback for a separately pre-custodied finite credential. No token is issued or rotated here.

For a two-app frozen scope, the transition requires all fourteen exact typed pre-complete receipts and the terminal state all fifteen, including the exact extended `handoff-family` receipt tied to the immutable empty-family checkpoint/token/digest. Stage counts derive from the frozen app list, not a hardcoded two-app exception. Missing stages, extras or a different family digest refuse. Empty targets are an independently captured owner-only fact; they never stand in for a family original or successor consent.

The frame preserves the exact owner HMAC/signature, original expiry, captured session manifest, canonical native completion lease and full native seal including receipt expiry. It rechecks current Auth user/session absence, zero owned homes/memberships/handoff plans/holds and the stopped principal. The historical original is not renewed AAL2 and grants no new deletion permission. Current retained app/Storage/notification/inventory coverage is still an independent mandatory provider through owning COMMIT.

`close(tx)` verifies the original, inserts an immutable private owner-terminal closure with no Auth FK, and changes only the exact scope stop binding from `processing` to `closed`. **It keeps `household_principal_fences.stopped=true` as the closed-user tombstone.** This is closure of the temporary worker binding, not re-enabling enrollment, account access, an epoch or ordinary old-JWT writes. No family holds are removed and the old family release is not called with an empty array.

The closure's deferred ALWAYS constraint requires global COMPLETE with its exact receipt on the same producing PID/XID, root status complete, both lease fields null and all immutable closure/original/checkpoint/custody/native facts intact. A raw SQL close cannot commit alone even without the JS hook. The JS reader owns a separate final hook which requires that same terminal state; `readSnapshot` remains hook-free for an existing owner verifier. A failure must roll back the whole transaction. The root adapter owns the COMPLETE stamp; it must not use an external connection or stamp it afterward in another transaction.

The direct-session exclusion now exposes a **separate** `bindTerminal`. Its new complete-root branch calls only the fixed `verify_ouchi_owner_terminal_root` RPC, checks the immutable closure/original root lease and the true terminal facts. `bind` remains processing-only and still refuses after root lease clearing. Each binding acquires the dedicated shared transaction key and pins the physical PID/XID; the session holder uses gap-free exclusive-to-shared downgrade. This keeps principal recreation excluded through the actual COMMIT even if the holder dies after the last successful verification. It does not exclude privileged orphan writes to other Auth tables or guard DDL: those remain external requirements.

A fresh completed-root transaction may read only with new terminal binding/current independent authority. Exact closure replay returns the sealed historical result without new erasure, original signing, session capture or expiry extension. The separate result reader reports completion only after exact terminal verification and repeats credential authorization at owning COMMIT. Notification and retention are deliberately `unconfirmed`: native completion is not proof of external message delivery or a globally adopted retention policy.

Local proof uses actual PostgreSQL 17.6 and GoTrue 2.197. It exercises 14→15 receipts, actual native seal, deferred raw-close refusal, late-coverage rollback of root/closure/binding together, completed-root replay/new binding, last-check holder termination with actual same-ID Admin create refusal through a real marker COMMIT, per-stage missing/extra/family-digest refusal, stopped-tombstone/closure-guard refusal, immutable original/session/native expiry preservation and late result-credential refusal. Other-app erasure, global privileged writer/DDL exclusion, credential/Keychain custody, real Storage/notification/retention remain explicit fixture boundaries. This is not production end-to-end evidence.

The SECURITY DEFINER SQL owners, runtime effective ACLs and direct connection capability need an approved restricted hosted profile before deployment. The local fixture explicitly grants only its test caller; this source creates no LOGIN or deployment grant. No schema or role in a shared project has been changed.
