# Generation session/prelogout boundary — design baseline

A local fourth-stage candidate now exists: `GenerationSessionCustodyReview.md`.
It chooses separate signed custody with ZERO native flag/child delta. A separate
local after-logout/before-native read gate is described in
`GenerationAfterLogoutAuthorityReview.md`; actual root dispatch/origin integration
and later native materialization/erasure authority below remain unimplemented.

The root independently reports normal paired3stages/current→historical custody,
unchanged5second final-seal expiry/refusal and later retry, and two-KB-household
completeness/fence isolation. This app has read that coordination evidence; this
document does not claim independently reexecuting those paired native tests.
Photo copy/unused cancellation are separate preparatory protocols and cannot
satisfy any native/session/erasure checkpoint.

## Exact blockers in current source

1. `generation_stage_prefix_matches` accepts only the first3 exact normal journal
   prefixes. Add ONLY the fourth normal `verify-sessions-before` receipt after its
   own immutable generation checkpoint; retain every prior proof, hole/extra-key
   refusal and producing deferred-COMMIT check. Do not permit future receipts in
   bulk or move any erasure earlier.
2. `generation_post_handoff_frame` and the current retention child matcher require
   `receipt_sessions_captured=false` and no native receipt-session child rows.
   A new exact session-capture witness is required to admit ONLY the corresponding
   canonical native row/child-set delta. Preserve the immutable native preparation
   and family handoff before/after originals; append a new witness, never retrofit
   their saved JSON. Unknown children and all other unexpected rows remain closed.
3. The old `ouchi_prelogout_frame` requires a legacy `familyCoverageDigest` and
   `shared_family_stage_contexts` receipt. New-generation normal receipts have no
   such extra field. Do NOT relabel them or reuse that old owner-zero proof/table
   row to get past the gate. A new generation-specific frame must use the actual
   new stage checkpoints, handoff witness and SAME family-original HMAC domain.
4. Canonical public `capture_maintenance_deletion_receipt_sessions` requires
   `records_erased=true` and object absence. It cannot truthfully run before app
   erasure at the fourth stage. Its body/ordering must stay unchanged. The prior
   reviewed NON-DELETING app-owned prelogout overlay is a mechanism reference,
   not a reusable owner-zero authority: a new generation-specific producer can
   capture exact live session IDs early, with its own typed context/provenance.
   If it populates native receipt rows/flag early, this must be an explicit
   witnessed generation delta, not a forced canonical success/flag. The later
   unchanged canonical producer can validate the already captured set after its
   own records-erased prerequisite; it must never fabricate missing live sessions
   after logout.

## Required new custody and current checks

Use a new append-only generation/whole-root/native-ID/native-lease/epoch-bound
custody row, with actual producer PID/XID, immutable complete session manifest
and the exact SAME original signatures/expiry and family-stage checkpoint digests.
Keep `OuchiMaintenance/family-generation-original/v1` originals unchanged; give
session custody its own explicit domain. Do not mint an owner-zero original or
reuse owner-zero epoch/session proofs. Store no raw refresh/bearer secrets in
transport/status results; any retained authentication-state evidence must use
reviewed nonreversible digests and private custody.

Before capturing, independently validate current owner AND all designated
successor originals/HMACs/Auth policy, complete actual owner Auth-session set,
Ouchi app epoch/session mappings and root-wide BOTH-app session/writer coverage.
Compare with the preserved generation preimage/roster: newly added, unmapped or
foreign-epoch sessions are refusal/review, not implicit inheritance. Ouchi's app
session subset alone is not a complete shared-Auth/global-logout manifest.

The dedicated capture must be non-deleting and SAME owning root transaction,
root-first locks, current native lease/enrollment stops, full snapshot/row checks,
exact scoped INSERT/flag-change contexts, repeated independent provider checks,
and immutable set-integrity checks at actual COMMIT. Lost ACK must read the same
committed custody, not renew Auth freshness, change originals or re-capture a
changed live set. A raw flag/partial checkpoint/orphan child set must fail.

## Current → historical is not one flag

After actual GoTrue global logout, the existing current-original reader MUST
continue refusing. Use a separate generation-specific before-native historical
reader for preserved originals/session custody, actual owner-session absence and
recorded real logout dispatch/acknowledgement. The existing family historical
fact proves neither logout/Auth absence nor worker identity or mutation authority.
No synthetic receipt, owner-zero table row, expired proof renewal or root COMPLETE
can replace this transition.

Later app erasure admits only its exact current generation stage/lease and owned
native deltas; predecessor receipts remain exact and required. Native erasure,
family/session readbacks, actual shared Auth removal and all after-Auth stages
must retain independent scoped capabilities and final checks. Keep the reviewed
owning shared transaction lock PLUS separate held exclusion interval through real
COMMIT; the superseded session-only final check had a recreation gap. That
exclusion/worker authority must be rebound to current generation custody, never
assumed from historical owner-zero success.

Photos remain closed at the old empty-file gate until full inventory, both-actor
inventory consent, retained-custody activation, unknown-writer resolution and
physical source disposition are separately proved. Unused file cancellation is
a reversal of preparation, not an erasure/session/COMPLETE capability. Hosted
runtime owners/permissions/ALL writers and retention adoption remain independent.
