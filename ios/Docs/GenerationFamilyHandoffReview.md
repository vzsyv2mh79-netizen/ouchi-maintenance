# Generation-specific empty-file handoff, post-delta originals and capture

Local review candidate, 2026-10-21. Extends the fixed new-domain original/early-claim protocol with lawful selected-owner replacement and the **unchanged canonical capture only after every selected home is handed off**. No legacy original re-signing/relabeling, old plan PK/immutable-guard change, record/Auth erasure, write-hold release, global family checkpoint or hosted activation.

## Fixed server interface and admission

`createGenerationFamilyHandoff(options)` takes the generation-original options plus mandatory independent `verifyHandoffAdmission(scope,tx,signal,phase:'before'|'after')`. It creates the fixed strict original provider internally; no supplied boolean identity/signature verifier or arbitrary SQL is accepted. `execute(scope,checkedTx)` returns true only after the actual fixed mutation and same-new-domain HMAC/full-state readbacks. `verifyAfter(scope,checkedTx)` is a hook-free **locking private current fact check**, not a READ ONLY HTTP/result capability or whole-account completion.

The actual physical owning transaction must supply query, AbortSignal and beforeCommit. Calls pin PID/XID; caught failure or repeat poisons the owning final hook. Scope/targets/lease must match exactly. Missing independent stage admission refuses; no default true provider. Before starting a new handoff, the old literal `verifyNoDispatch` and new before-stage admission are both required. After a verified durable handoff, the literal no-transfer predicate is not relabeled as true: the new after-stage admission must cover all remaining writers/DDL/Storage/other dispatch and accept only this exact proven database transfer. The phase comes from the fixed private captured fact, never client input. Unknown, unbound or external outcomes refuse.

## Atomic lawful delta

1. Exact live processing root/planned lease/empty receipts, generation/pointer/native stop, complete current new-domain owner/all-successor issuer originals and independent server HMAC checks are required. The SQL RPC also validates the complete current immutable issuer set. No operation occurs under requested, expired, missing or foreign custody.
2. Before any update, a private immutable witness records the exact native prepared footprint, every originally owned home's complete snapshot, outside memberships and all original payloads/signatures/policy settings. Native observation gains actual home-incarnation evidence under a byte-identical private delegate. Fresh generation/preimage creation must occur **after installing this whole extension**; old catalog/preimages are never retrofitted.
3. A narrow transient actual PID/XID/generation/home context permits only the selected owner replacement. Existing home writer guards remain installed. Before/after snapshots include home/member/product/task/history content, file/write metadata and frozen write routes. The only allowed home change is owner_id from original owner to that home's signed successor. Unselected private homes and outside memberships remain identical. New homes, partial roster, file metadata or unknown changes refuse.
4. After every selected home has a matching immutable receipt and only then, the actual existing canonical capture runs with the exact native lease. The unchanged owned-family guard must pass. Its reviewed body SHA is pinned to `77108701d1e59146d1f9cfd40e9293bc1712997023dfe94a0921c2fdfbefdd1c`. The capture context admits only the captured flag/updated_at update and exact false-enabled no-op updates. No object inventory row INSERT, Auth mutation or content erasure is admitted. Empty inventory is still required.
5. The witness becomes captured with exact after-state/snapshots. A deferred ALWAYS check requires the complete captured result/current original set at actual producing COMMIT; partial staging cannot commit. The original raw preimages and all new-domain signed originals/expiry stay unchanged. Lost-ack retries verify the durable witness/current originals and do not repeat handoff, capture or renew any time.

The old household-handoff predicate, family-original frame, native observation and native writer dispatcher bodies are byte-compared before delegation. Outside the exact new context or captured witness, old semantics remain. The new post-delta frame recognizes only this complete legitimate immutable delta: same generation/scope/lease/pointers, exact originals, same Auth/epoch/stop state, selected ownership replacement, unchanged outside/private/family data, captured=true with other native fields unchanged, and only its own admitted transfer marker. Extra unknown dispatch invalidates current authority. Signature validation uses the **same** new-domain originals and generation-derived original plan, not regenerated legacy proofs.

## Scope boundary with the root coordinator

This candidate keeps root receipts empty throughout the private local handoff/capture exercise. It does **not** write a global `handoff-family` checkpoint or modify the existing shared-family checkpoint/processing/COMPLETE guards to make a new format pass. The current public requested_at intake, both-app root stage/checkpoint, native erasure/seal, result retention and Auth-removal interval still need independent integration. No global stage/whole-retirement success is inferred from captured=true.

Owner stop/tombstone, generation current pointers and old frozen routes remain. Ordinary family writes are still held after transfer. Releasing/reassigning those routes/holds requires a separately exact global-finality protocol; this candidate never reopens them. Current post-delta reader is limited to live processing/native leases, empty root receipts, unchanged data and no erasure/extra dispatch. It is not a general after-Auth/result-history reader and does not extend TOTP/native/result expiry.

## Evidence

Actual isolated PostgreSQL17.6/GoTrue2.197 uses real owner+two successor TOTP originals across two shared homes, plus an unselected private home/product and outside membership. Real selected owner changes and canonical capture succeed; full family/private/outside data remains, ordinary family write remains held, old legacy plans and all four new-domain originals are byte-identical. Fresh post-delta Auth/HMAC read and lost-ack retry preserve the witness. Late admission loss rolls ownership, native capture, witness/context and transfer marker back. Unknown subsequent erase admission refuses without repeating or undoing the committed ownership/data. Runtime raw helper/table/mutation and immutable witness changes refuse.

Unit checks distinguish literal pre-dispatch refusal from after-stage admission, reject missing stage provider/wrong HMAC/foreign scope/unchecked transaction/unexpected post-facts, and poison late policy/admission/PID-XID drift or repeats. Private core/observers still retain fixture DDL ownership; PUBLIC EXECUTE is revoked and runtime receives only fixed execute/verify RPCs. This is NOT a reviewed hosted least-privilege owner/ACL profile.

Remaining: real root-family checkpoint/erasure/finality/hold release; files/capacity/actual Storage uncertainty; operator recovery and result/native retention alignment; all-writer/effective-role registry; explicit retention/access policy for private family snapshots, original/session/incarnation data. No new policy/TTL/pruner, hosted permissions/migration, real user operation, fee, publication or production activation is adopted.

Receipt deadline incompatibility remains explicit: the new preparation has no formal native retention check, and its incoming-child-empty gate currently refuses a nonempty deletion_retention_checks row before claim/capture. Adding one cannot simply be exempted or fabricated. A future reviewed exact scoped-evidence admission and cancellation disposition must be designed alongside the real result resolver and approved independent policy/other-evidence deadlines. The existing maintenance_deletion_retention_is_confirmed also requires identity erasure, so it is not an initial-prepare authority. No fixture600/300-second duration is adopted as policy here.
